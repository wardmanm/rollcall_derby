# Auth in the Web App (#11) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People use the web app to:
- set up a fresh install;
- sign in and out, and change their password;
- manage users, if they're Admins.

Every rcl app's pages sit behind sign-in, while the OBS overlay stays public. rcl-core's home page lists the installed apps.

**Architecture:**
- **The server (Task 1):**
  - `GET /api/core/auth/me` also returns the permissions your role holds, so the web app hides what you can't use by permission, not by role (ADR-0018).
  - Logout always works.
  - Validation errors are plain sentences.
- **The web SDK (Task 2)** adds `SignInGate`, which wraps each app's layout:
  - it sends people to rcl-core's setup, sign-in or change-password page with `?next=`, and they come back afterwards;
  - `useGoTo` moves through the app's own router, or loads another app's page;
  - the header gains links by permission and an account menu;
  - a request refused because the session ended makes the app ask the server again who's signed in.
- **rcl-core's web app (Tasks 3–4)** gets:
  - the pages before sign-in, outside the gate: setup, sign-in and change password;
  - the app launcher as its home page;
  - the Users page.

  The Producer app puts its pages behind the same gate.
- **Forms** check their input with the contract's Zod schemas before sending, so people see the same words the server would use.

**Tech Stack:** React 19, React Router 8, Mantine 9, Redux Toolkit 2 / RTK Query, Zod 4 via the contracts, Vitest 5 with React Testing Library (jsdom), Storybook 10 story tests with axe, Playwright. **No new dependencies.**

**Specs:**
- [`design-docs/specs/2026-10-02-auth-skeleton-design.md`](../specs/2026-10-02-auth-skeleton-design.md) "Web app" and "Tests": the auth gate, the pages, the user menu, and the Playwright flow.
- [`design-docs/specs/2026-10-07-rollcall-split-design.md`](../specs/2026-10-07-rollcall-split-design.md) "URL scheme": `SignInGate` and `next`, and `GET /api/core/apps` feeding the launcher.
- The behavior: [`docs/features/users-and-access.md`](../../docs/features/users-and-access.md), R1–R4.

## Global Constraints

- **Hard rule 3:** browsers talk only to the Rollcall server.
- **Hard rule 4:** nothing is loaded from the internet.
- **Hard rule 5:** every route checks the caller. **Hiding UI is not access control**: the web app hides by permission only for convenience, and the server refuses anyway.
- **Hard rule 6:** server data lives only in RTK Query, never copied into slices.
- **Responses are validated** with the contract's schemas in `transformResponse` (ADR-0019).
- **From the split spec:** "Login lives in core-web. `SignInGate` in web-sdk sends signed-out users to `/core/login?next=…`. `next` must start with `/` and not `//`."
  - `/\` is refused too, since browsers read it as `//`.
- **From the auth skeleton spec:** "an auth gate in the layout picks the page":
  - `needsSetup` sends you to setup, which shows "open this page on the server machine" when `canSetupHere` is false;
  - no session sends you to sign in;
  - `mustChangePassword` sends you to change password.
- **Pages:** Setup, Login and Change password. The Users page (Admin only) can create a user (showing the temporary password once, with a copy button), change a role, reset a password, sign a user out and delete a user.
- **Header:** a user menu with your username, a role badge, Change password and Log out. A **Users** link appears for Admins.
- **The OBS overlay stays public:** `/producer/overlay` is a separate entry that never imports the web SDK or Mantine (`rcl-producer/web/src/overlay/bundle.test.ts`).
- **Each new shared component gets a story,** and story tests fail on any axe violation (ADR-0015).
- **No new dependencies,** and no lockfile change.
- **TypeScript rules:** `.ts`/`.tsx` extensions on relative imports. No `as` casts in source outside tests, and no new inline `oxlint-disable`.
- **Every commit passes `yarn format && yarn check`.** Tasks 2–4 also pass `yarn build && yarn test:stories && yarn test:e2e`.
- **Commits** follow Conventional Commits, with scope `rcl-core`, `sdk` or `repo`.

## Review Focus

1. **A session that ends while a page is open:** the 30-day cap, an Admin signing you out, or a password reset. The next refused request (`unauthenticated` or `password_change_required`) must make the app ask again who's signed in, so the gate sends the person to sign in and back. Test in Task 2: `api.test.ts`, "a request refused because the session ended".
2. **A `next` that leads somewhere else:** `//evil.example`, `/\evil.example` or a full URL must land on rcl-core's home, never on another site. Tests in Task 2 (`core-pages.test.ts`) and Task 3 (`LoginPage.test.tsx`, "never goes on to another site").
3. **The venue network over plain HTTP:**
   - Browsers block copying there, so the temporary password must stay selectable without a Copy button.
   - Setup from another device must name the `localhost` address with the right port.

   Tests in Task 4 (`UsersPage.test.tsx`, the two clipboard tests) and Task 3 (`SetupPage.test.tsx`, "on any other device").
4. **A slow network right after setup or a password change:** going on before the server confirms lets the gate see the old answer and send the person back. Tests in Task 3: the slow second answers in `SetupPage.test.tsx` and `ChangePasswordPage.test.tsx`. The e2e run found this race.
5. **Someone without the permission opening `/core/users` directly:** they see "Only Admins can manage users.", and the server answers `403`. Tests in Task 4 (`UsersPage.test.tsx`) and the e2e flow (`page.request.get('/api/core/users')` → 403).

## Decisions this plan makes

The specs leave these open. Each is decided here so implementers and reviewers don't have to guess.

**Server and contract:**
- **`GET /api/core/auth/me` returns `CurrentUser`:** a `SessionUser` plus `permissions`, the keys the caller's role holds across every hosted app. Login, setup and password changes keep replying with a `SessionUser`, and the web app asks `me` again afterwards.
- **Logout is public:** it always answers `204` and clears the cookie, even with no session. The cross-site check still applies, because every `/api` write gets it. The route inventory pins the change.
- **A validation error's `message`** is each problem's own words, joined by spaces. The web app checks forms with the same schemas first, so people rarely see it.
- **Body-less POSTs send `{}`**, as the split spec's issue list says. DELETE sends no body.

**The sign-in gate and moving between apps:**
- **`SignInGate` wraps each app's layout route.** rcl-core's setup, sign-in and change-password routes sit outside it. The pages' addresses are `CORE_PAGES`; `/core/change-password` follows the auth skeleton spec.
- **Moving between apps:** `useGoTo` uses the router for a page below this app's base, and otherwise loads the page (`browser.replace`, replaced with a spy in tests). Every move replaces the history entry, so Back doesn't bounce off the gate.
- **The gate trusts only the server's answers:** while it's still asking, it shows a loader; if the server can't be reached, it shows an error with "Try again". A refused request (`unauthenticated` or `password_change_required`) makes it ask again. Pages that change those answers (setup, password change) wait for the server's new answer before going on.

**Pages and components:**
- **Forms use plain React state with Mantine inputs**, not `@mantine/form`, so nothing new is installed. Roles use `NativeSelect`, which jsdom can drive and screen readers know. Confirmations are Mantine `Modal`s.
- **Accessibility:**
  - The shared Mantine `theme` uses `primaryShade` 8, because shade 6 fails 4.5:1 contrast with white text.
  - Notices use gray, because yellow and orange fail contrast.
  - The account menu has no focus placeholder, and its button is named by its visible text.
- **Temporary passwords** are shown in a read-only box that selects itself on focus, plus Copy only where the browser allows clipboard access (HTTPS or `localhost`).
- **The launcher** lists the hosted apps that have a web app, other than rcl-core itself, as cards that load each app's page.
- **Unknown addresses** inside either app show `PageNotFound` instead of React Router's error page.
- **Stories** cover the new shared components: `UserMenu`, `SignInGate` and `PageNotFound`. rcl-core's pages aren't shared components, so they're tested with React Testing Library only.

**End-to-end tests:**
- **Each Playwright run gets a fresh data folder,** kept in `ROLLCALL_E2E_DATA_DIR` so all workers agree, and removed by `global-teardown.ts`.
- **`accounts.spec.ts` runs in order.** `admin.spec.ts` and `producer.spec.ts` fold into it. If one of its tests fails in CI, the retry reruns the group on a server that's already set up, so the retry fails too: never a false pass.

**Not done here** (deferred minors from earlier reviews, or later issues):
- the password-change reply using the user from before the hash;
- stories with axe checks for rcl-core's pages;
- an app's own route at `/api/<id>`;
- reserved app ids;
- the open questions on Announcer access.

```ts
import type { FastifyError, FastifyReply, FastifyRequest } from 'fastify';
import { ApiErrorSchema } from '@rollcall/core-contract';

// Every /api route lists this in its response schemas. It documents the error shape, and lets the route send 4xx
// replies: Fastify's types only let a typed route send the status codes its response schema declares (at runtime,
// a status without a schema goes out unchecked).
export const ERROR_RESPONSES = { '4xx': ApiErrorSchema };

const ERROR_CODES: Partial<Record<number, string>> = {
  400: 'bad_request',
  404: 'not_found',
  413: 'payload_too_large',
  415: 'unsupported_media_type',
  429: 'rate_limited',
};

// Errors that Fastify and its plugins raise (malformed JSON, the wrong content type, rate limits, crashes), in the
// same { error, message? } shape as our own replies. Server errors are logged, never echoed: their text can hold
// SQL or file paths.
export function sendApiError(error: FastifyError, request: FastifyRequest, reply: FastifyReply) {
  // A body, path or query that fails its route schema (ADR-0014). The message is each problem's own words, such as
  // "Use at least 10 characters", without Fastify's "body/password" prefix: the web app shows it as it is.
  if (error.validation) {
    const message = error.validation.flatMap((problem) => problem.message ?? []).join(' ');
    return reply.code(400).send({ error: 'validation_failed', message: message || error.message });
  }
  const status = error.statusCode !== undefined && error.statusCode >= 400 ? error.statusCode : 500;
  if (status >= 500) {
    request.log.error({ err: error }, 'Request failed');
    return reply.code(500).send({ error: 'internal_error' });
  }
  return reply.code(status).send({ error: ERROR_CODES[status] ?? 'bad_request', message: error.message });
}
```

Replace `rcl-core/server/src/routes/auth.ts` with:

```ts
import type { FastifyInstance } from 'fastify';
import type { ZodTypeProvider } from 'fastify-type-provider-zod';
import { z } from 'zod';
import {
  ChangePasswordRequestSchema,
  CurrentUserSchema,
  LoginRequestSchema,
  SessionUserSchema,
  type CurrentUser,
} from '@rollcall/core-contract';
import type { AppDatabase } from '../db.ts';
import type { Access } from '../auth/access.ts';
import { clearSessionCookie, setSessionCookie } from '../auth/guard.ts';
import { dummyHash, hashPassword, verifyPassword } from '../auth/passwords.ts';
import { createSession, revokeSession, revokeUserSessions } from '../auth/sessions.ts';
import { findUserForLogin, setPassword, toSessionUser } from '../auth/users.ts';
import { ERROR_RESPONSES } from '../http.ts';
import { AUTH_RATE_LIMIT } from './setup.ts';

const INVALID_CREDENTIALS = { error: 'invalid_credentials' };
const UNAUTHENTICATED = { error: 'unauthenticated' };
// `me` and `password` must work while a password change is pending, or the user could never make it.
const SIGNED_IN_PENDING_OK: Access = { signedIn: true, allowPendingPasswordChange: true };

export function registerAuthRoutes(fastify: FastifyInstance, db: AppDatabase): void {
  const api = fastify.withTypeProvider<ZodTypeProvider>();

  api.post(
    '/auth/login',
    {
      config: { rateLimit: AUTH_RATE_LIMIT, access: { public: 'Signing in' } },
      // A malformed body must look and take the same as wrong credentials, so the handler deals with it.
      attachValidation: true,
      schema: {
        tags: ['core/auth'],
        summary: 'Log in',
        body: LoginRequestSchema,
        response: { 200: SessionUserSchema, ...ERROR_RESPONSES },
      },
    },
    async (request, reply) => {
      const body = request.validationError ? null : request.body;
      const user = body ? findUserForLogin(db, body.username) : null;
      const ok = await verifyPassword(body?.password ?? '', user?.passwordHash ?? (await dummyHash()));
      if (!user || !ok) return reply.code(401).send(INVALID_CREDENTIALS);

      // Whoever was signed in on this browser is signed out, so a shared tablet doesn't keep their session alive.
      if (request.principal) revokeSession(db, request.principal.token);

      const session = createSession(db, user.id);
      setSessionCookie(reply, request, session.token, session.expiresAt);
      return toSessionUser(user);
    },
  );

  api.post(
    '/auth/logout',
    {
      config: {
        access: { public: 'Logging out always works and clears the cookie, even when the session has already ended' },
      },
      schema: { tags: ['core/auth'], summary: 'Log out', response: { 204: z.undefined(), ...ERROR_RESPONSES } },
    },
    async (request, reply) => {
      if (request.principal) revokeSession(db, request.principal.token);
      clearSessionCookie(reply);
      return reply.code(204).send();
    },
  );

  api.get(
    '/auth/me',
    {
      config: { access: SIGNED_IN_PENDING_OK },
      schema: { tags: ['core/auth'], summary: 'Who am I?', response: { 200: CurrentUserSchema, ...ERROR_RESPONSES } },
    },
    async (request, reply) => {
      const user = request.principal?.user;
      if (!user) return reply.code(401).send(UNAUTHENTICATED);
      const { permissions } = request.server.hostedApps;
      const held = permissions.all.filter((def) => permissions.granted(user.role, def.key)).map((def) => def.key);
      return { ...user, permissions: held } satisfies CurrentUser;
    },
  );

  api.post(
    '/auth/password',
    {
      config: { rateLimit: AUTH_RATE_LIMIT, access: SIGNED_IN_PENDING_OK },
      schema: {
        tags: ['core/auth'],
        summary: 'Change your own password',
        body: ChangePasswordRequestSchema,
        response: { 200: SessionUserSchema, ...ERROR_RESPONSES },
      },
    },
    async (request, reply) => {
      const user = request.principal?.user;
      if (!user) return reply.code(401).send(UNAUTHENTICATED);
      const { currentPassword, newPassword } = request.body;
      if (newPassword.toLowerCase() === user.username) {
        return reply.code(400).send({ error: 'validation_failed', message: 'The password must not be the username' });
      }
      const record = findUserForLogin(db, user.username);
      if (!record || !(await verifyPassword(currentPassword, record.passwordHash))) {
        return reply.code(400).send({ error: 'wrong_password' });
      }
      const passwordHash = await hashPassword(newPassword);
      // Signed out (by an Admin's reset, say) while the password was hashing: don't overwrite the reset.
      const denial = request.recheckAccess();
      if (denial) return reply.code(denial.status).send({ error: denial.error });
      setPassword(db, record.id, passwordHash, { mustChangePassword: false });
      if (request.principal) revokeUserSessions(db, record.id, { exceptToken: request.principal.token });
      return { ...user, mustChangePassword: false };
    },
  );
}
```

// Leaving this app's router: a full page load, replacing the current history entry. Tests replace it with a spy,
// since jsdom can't load pages.
export const browser = {
  replace(url: string): void {
    window.location.replace(url);
  },
};

/**
 * Goes to a page of any rcl app, replacing the current history entry: through this app's router when the page is
 * below this app's base (`/core/…` in rcl-core), otherwise with a full page load.
 */
export function useGoTo(): (url: string) => void {
  const navigate = useNavigate();
  const base = useHref('/');
  return useCallback(
    (url: string) => {
      const prefix = base.endsWith('/') ? base : `${base}/`;
      if (url === base || url.startsWith(prefix)) void navigate(url.slice(prefix.length - 1), { replace: true });
      else browser.replace(url);
    },
    [navigate, base],
  );
}

import { ApiErrorSchema } from '@rollcall/core-contract';

// The server's error code and message for a failed request (`{ error, message? }`), if it sent one. RTK Query puts
// the reply body in `error.data`; a network failure has none.
export function apiError(error: unknown): { code: string; message?: string } | undefined {
  const data = typeof error === 'object' && error !== null && 'data' in error ? error.data : undefined;
  const parsed = ApiErrorSchema.safeParse(data);
  return parsed.success ? { code: parsed.data.error, message: parsed.data.message } : undefined;
}

import {
  createApi,
  fetchBaseQuery,
  type BaseQueryFn,
  type FetchArgs,
  type FetchBaseQueryError,
} from '@reduxjs/toolkit/query/react';
import {
  CurrentUserSchema,
  SetupStatusSchema,
  type CurrentUser,
  type HealthResponse,
  type SetupStatus,
} from '@rollcall/core-contract';
import { apiError } from './errors.ts';
import { parseHealth } from './health.ts';

// Absolute so it also works where relative URLs can't be resolved (e.g. Node's fetch in tests).
const fetchFromServer = fetchBaseQuery({ baseUrl: `${window.location.origin}/api/` });

// A request refused because the session ended (`unauthenticated`) or a password change is now due means "who's signed
// in" has changed: ask again, so the sign-in gate sends the person to the right page.
const SESSION_CHANGED = new Set(['unauthenticated', 'password_change_required']);

const baseQuery: BaseQueryFn<string | FetchArgs, unknown, FetchBaseQueryError> = async (args, queryApi, extra) => {
  const result = await fetchFromServer(args, queryApi, extra);
  const code = apiError(result.error)?.code;
  if (code && SESSION_CHANGED.has(code) && queryApi.endpoint !== 'getMe') {
    queryApi.dispatch(api.util.invalidateTags(['Me']));
  }
  return result;
};

// All server data lives in RTK Query, never copied into slices (hard rule 6, ADR-0003). Responses are validated
// against the apps' Zod contracts (ADR-0019). Each app adds its own endpoints with `api.injectEndpoints`.
export const api = createApi({
  reducerPath: 'api',
  baseQuery,
  tagTypes: ['Me', 'Setup'],
  endpoints: (build) => ({
    getHealth: build.query<HealthResponse, void>({
      query: () => 'core/health',
      transformResponse: (response: unknown) => parseHealth(response),
    }),
    getSetupStatus: build.query<SetupStatus, void>({
      query: () => 'core/setup',
      transformResponse: (response: unknown) => SetupStatusSchema.parse(response),
      providesTags: ['Setup'],
    }),
    getMe: build.query<CurrentUser, void>({
      query: () => 'core/auth/me',
      transformResponse: (response: unknown) => CurrentUserSchema.parse(response),
      providesTags: ['Me'],
    }),
    // Body-less POSTs send `{}`: the server refuses an empty body labelled as JSON.
    logout: build.mutation<void, void>({
      query: () => ({ url: 'core/auth/logout', method: 'POST', body: {} }),
      invalidatesTags: ['Me'],
    }),
  }),
});

export const { useGetHealthQuery, useGetSetupStatusQuery, useGetMeQuery, useLogoutMutation } = api;

import { skipToken } from '@reduxjs/toolkit/query/react';
import { useHref, useLocation } from 'react-router';
import { useGetMeQuery, useGetSetupStatusQuery } from './api.ts';
import { CORE_PAGES, withNext } from './core-pages.ts';

// Shows its pages only to someone signed in who has chosen their own password (split spec). Anyone else goes to
// rcl-core's setup, sign-in or change-password page, which bring them back here afterwards. It only hides pages:
// the server checks every request (hard rule 5).
export function SignInGate({ children }: { children: ReactNode }) {
  const setup = useGetSetupStatusQuery();
  const me = useGetMeQuery(setup.data?.needsSetup === false ? undefined : skipToken);
  const here = useHref(useLocation());
  const goTo = useGoTo();

  const target = setup.data?.needsSetup
    ? CORE_PAGES.setup
    : apiError(me.error)?.code === 'unauthenticated'
      ? withNext(CORE_PAGES.signIn, here)
      : me.data?.mustChangePassword
        ? withNext(CORE_PAGES.changePassword, here)
        : undefined;
  useEffect(() => {
    if (target) goTo(target);
  }, [target, goTo]);

  if (!target && (setup.isError || me.isError)) {
    return (
      <Center mih="100vh">
        <Stack align="center">
          <Alert color="red" title="Can't reach the Rollcall server">
            Check that the server is running and this device is on the venue network.
          </Alert>
          <Button
            onClick={() => {
              void setup.refetch();
              if (setup.data) void me.refetch();
            }}
          >
            Try again
          </Button>
        </Stack>
      </Center>
    );
  }
  if (target || !me.data) {
    return (
      <Center mih="100vh">
        <output aria-label="Checking who's signed in">
          <Loader />
        </output>
      </Center>
    );
  }
  return children;
}

import { apiError } from '@rollcall/web-sdk';

/** A failed check of a form against a contract schema: Zod's issues, each naming its field. */
interface Problems {
  issues: readonly { path: readonly PropertyKey[]; message: string }[];
}

/** The first problem with each field, in the contract's own words, to show under that field's input. */
export function fieldErrors(problems: Problems): Record<string, string> {
  const errors: Record<string, string> = {};
  for (const issue of problems.issues) errors[String(issue.path[0] ?? '')] ??= issue.message;
  return errors;
}

const SENTENCES: Partial<Record<string, string>> = {
  rate_limited: 'Too many attempts from this device. Wait a minute, then try again.',
  forbidden: "Your account can't do that.",
};

/**
 * What to tell a person about a failed request: this page's sentence for the server's error code, else a common one,
 * else the server's own message (validation problems, the last-Admin rule).
 */
export function problemWith(error: unknown, sentences: Partial<Record<string, string>> = {}): string {
  const reply = apiError(error);
  if (!reply) return "Can't reach the Rollcall server. Check that it's running, then try again.";
  return sentences[reply.code] ?? SENTENCES[reply.code] ?? reply.message ?? 'Something went wrong. Try again.';
}

// User management for Admins (users-and-access R3). Hiding it from others is only for convenience: the server refuses

export function UsersPage() {
  const { data: me } = useGetMeQuery();

function ManageUsers({ me }: { me: CurrentUser }) {
  const users = useGetUsersQuery();
  const [updateRole] = useUpdateUserRoleMutation();
  const [resetPassword] = useResetPasswordMutation();
  const [signOut] = useSignOutUserMutation();
  const [deleteUser] = useDeleteUserMutation();
  const [shown, setShown] = useState<ShownPassword | null>(null);
  const [confirming, setConfirming] = useState<Confirmation | null>(null);
  const [problem, setProblem] = useState<string | null>(null);

  // Runs a request, and says what went wrong if it fails.
  const attempt = async <T extends { error?: unknown }>(request: Promise<T>) => {
    setProblem(null);
    const result = await request;
    if (result.error) setProblem(problemWith(result.error, SENTENCES));
    return result;
  };

  const confirmed = async () => {
    const action = confirming;
    setConfirming(null);
    if (action) await action.run();
  };

  return (
    <Stack maw={880}>
      <Title order={2}>Users</Title>
      <CreateUser onCreated={setShown} />
      {problem && (
        <Alert color="red" withCloseButton closeButtonLabel="Dismiss" onClose={() => setProblem(null)}>
          {problem}
        </Alert>
      )}
      {users.isError && <Alert color="red">{problemWith(users.error)}</Alert>}
      <Table>
        <Table.Thead>
          <Table.Tr>
            <Table.Th>Username</Table.Th>
            <Table.Th>Role</Table.Th>
            <Table.Th>Created</Table.Th>
            <Table.Th>
              <VisuallyHidden>Actions</VisuallyHidden>
            </Table.Th>
          </Table.Tr>
        </Table.Thead>
        <Table.Tbody>
          {users.data?.map((user) => (
            <UserRow
              key={user.id}
              user={user}
              isYou={user.id === me.id}
              onRole={(role) => void attempt(updateRole({ id: user.id, role }))}
              onReset={() =>
                setConfirming({
                  title: `Reset ${user.username}'s password?`,
                  message: 'They are signed out everywhere and get a temporary password, shown to you once.',
                  action: 'Reset password',
                  run: async () => {
                    const result = await attempt(resetPassword(user.id));
                    if (result.data) setShown({ username: user.username, password: result.data.temporaryPassword });
                  },
                })
              }
              onSignOut={() =>
                setConfirming({
                  title: `Sign ${user.username} out everywhere?`,
                  message: 'Every device they use has to sign in again, even mid-game.',
                  action: 'Sign out',

      onCreated({ username: result.data.user.username, password: result.data.temporaryPassword });
    }

            label="Username"
            value={username}
            onChange={(event) => setUsername(event.currentTarget.value)}
            error={errors.username}
          />
          <NativeSelect
            label="Role"
            data={ROLE_OPTIONS}
            value={role}
            onChange={(event) => {

              if (isRole(value)) setRole(value);
