# API Keys for Devices and Scripts (#7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Devices and scripts on the venue network, such as Bitfocus Companion, a Stream Deck or a laptop script, call rcl-core with an API key that an Admin creates, scopes to permissions and can revoke.

**Architecture:**
- **A key is its own kind of caller** (`{ kind: 'apiKey', key }`, next to sessions), with its own permissions and no user or role.
- **`resolvePrincipal` reads the `Authorization` header first.** When it's present, the session cookie is ignored and the cross-site check is skipped.
- **`deny` handles keys:**
  - routes for any signed-in user refuse them;
  - permission routes let a key through only if it holds the permission, and it isn't people-only (`PermissionDef.peopleOnly`).
- **Storage:** keys live in a new `api_keys` table, hashed, with optional expiry and a last-used time.
- **Management:** Admins use `/api/core/api-keys` and a new API keys page.

**Tech Stack:** Fastify 5 + Drizzle 0.45 (new migration), Zod 4 contracts, React 19 + Mantine 9 + RTK Query, Vitest 5, Playwright. **No new dependencies.**

**Spec:** [`design-docs/specs/2026-10-14-api-keys-design.md`](../specs/2026-10-14-api-keys-design.md) (approved). Issue **#7**.

## Global Constraints

- **From the spec:**
  - **Format:** "`rcl_` followed by 32 random bytes as base64url (43 characters), 47 in all".
  - **Shown once:** "The key appears in exactly one response, the one that creates it."
  - **Storage:** "`token_hash`: … the SHA-256 of the key, hex-encoded … **The key itself is never stored.**"
  - **Cookie:** "If the header is present, **only it counts.** … The session cookie is never used as a fallback."
  - **Cross-site check:** "The cross-site check … is **skipped when an `Authorization` header is present.**"
  - **Signed-in routes:** "`signedIn`: `403 forbidden`."
  - **Permission routes:** "`permission`: allowed only if the key holds that exact permission … Keys have no role, so the Admin shortcut doesn't apply."
  - **Expiry:** "`expiresIn` is one of `never`, `1d`, `7d`, `30d` or `1y` (24 hours, 7 days, 30 days, 365 days), counted from creation."
  - **People-only:** "`core:users.manage` becomes `peopleOnly`. A new permission `core:api-keys.manage` … `roles: []` (Admin only), `peopleOnly`."
  - **Live connections:** "Socket.IO ignores the `Authorization` header."
- **Hard rules:**
  - Rule 5: authorization happens on the server, and the web app hides the API keys page by permission only for convenience.
  - Rule 6: server data lives only in RTK Query.
  - Rule 4: works offline, so nothing is loaded from the internet.
- **Database:** never edit an existing migration's SQL. The new table comes from `db:generate --name api_keys`.
- **TypeScript and lint:** no new dependencies, no `as` casts in source outside tests, and no new `oxlint-disable`.
- **Every commit passes `yarn format && yarn check`.** Task 4 also passes `yarn build && yarn test:stories && yarn test:e2e`.
- **Commits** follow Conventional Commits with scope `rcl-core` or `repo`, and end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. Task 5's commit says `Closes #7`.
- **Nothing is pushed** without Mike's explicit OK (Task 6).

## Review Focus

1. **A key sent alongside a session cookie,** such as a script run from a signed-in browser, or Playwright's `page.request`. A bad key must never fall back to the Admin's session, and a good key must never act as the Admin. Tests:
   - Task 2: `api-key-requests.test.ts`, "ignores the session cookie, even an Admin's";
   - Task 4: the e2e test, whose requests carry the Admin's cookie.
2. **A key holding a permission that later became people-only** (or a hand-edited database). It must be refused anyway. Test in Task 2: "never uses a people-only permission, even one a key was given before it became people-only".
3. **A key revoked or expiring while devices use it.** The next request gets `401`, a request already under way is stopped by its re-check, and the expired key stays listed so the Admin sees why. Tests:
   - Task 2: the revoked, expired and mid-request tests;
   - Task 4: the page's Expired badge.
4. **Malformed `Authorization` headers:** `Basic …`, a bare `Bearer`, an empty value or a made-up key. Each must get `401`, never the cookie's user. Tests:
   - Task 2: "is refused with a wrong, revoked or expired key, or a header that is not a bearer key";
   - Task 3: the inventory's wrong-key sweep.
5. **A device opening a live connection with a key.** It must be refused, because namespaces take sessions only. Test in Task 2: `realtime.test.ts`, "takes no API keys: a live connection needs a session".

## Decisions this plan makes

The spec leaves these open. Each is decided here so implementers and reviewers don't have to guess.

**Server:**
- **Shared token helpers:** sessions and keys share `auth/tokens.ts` (`newToken`, `hashToken`); sessions previously had their own copy.
- **Last used:** `findApiKey` records the time at most once a minute, in the same call that finds the key, as `findSession` does.
- **The header:** `Bearer` is matched without regard to case, followed by one token (`/^Bearer\s+(\S+)\s*$/i`).
- **People-only is checked twice:** at creation, and again on every request, in `deny`.
- **`created_by`** is the creating Admin's username, taken from `userOf(request.principal)`.
- **Names** must be unique as an exact match. The check runs with no `await` before the insert.
- **Creating a key:** repeated permissions are kept once, and `not_grantable` names each refused permission.
- **The API explorer** says for each operation whether keys may call it ("Not API keys." / "Also API keys that hold it.").
- **Core's migration count test** reads `drizzle/meta/_journal.json`, so new migrations don't break it.

**Tests:**
- **The route inventory's helpers** send `{ cookies?, headers? }`. A test app, `KEYS_PROBE_APP`, supplies a route a key may call.

**Web app:**
- **`TemporaryPassword` becomes `ShowOnce`,** used for both temporary passwords and new keys.
- **The `ADMIN` test fixture** holds `core:api-keys.manage` too, as a real Admin does.
- **"Expired"** is judged against when the page opened, because React's purity lint forbids `Date.now()` while rendering. Its badge is gray, which passes the contrast checks.

**End to end and docs:**
- **The e2e key test** runs at the end of the ordered accounts flow, using `page.request` so the Admin's cookie rides along.
- **ADR numbering:** ADR-0020 is API keys, so the split spec's per-app releases ADR becomes 0021.

```ts
import { describe, expect, it } from 'vitest';
import { ApiKeySchema, type ApiKeyExpiry } from '@rollcall/core-contract';
import { openMemoryDatabase } from '../db.ts';
import { apiKeyNameTaken, createApiKey, findApiKey, listApiKeys, revokeApiKey } from './api-keys.ts';

const NOW = new Date('2026-10-16T12:00:00.000Z');
const minutes = (n: number) => new Date(NOW.getTime() + n * 60_000);

function withKey(expiresIn: ApiKeyExpiry = 'never', permissions: string[] = ['demo:things.read']) {
  const { db } = openMemoryDatabase();
  const created = createApiKey(db, { name: 'Stream Deck', permissions, expiresIn, createdBy: 'admin' }, NOW);
  return { db, ...created };
}

const expiry = (expiresIn: ApiKeyExpiry) => withKey(expiresIn).apiKey.expiresAt;

describe('API keys', () => {
  it('are rcl_ and 43 characters, shown once, with only their hash and first characters stored', () => {
    const { db, apiKey, key } = withKey();
    expect(key).toMatch(/^rcl_[\w-]{43}$/);
    expect(ApiKeySchema.parse(apiKey)).toEqual({
      id: apiKey.id,
      name: 'Stream Deck',
      prefix: key.slice(0, 8),
      permissions: ['demo:things.read'],
      createdAt: NOW.toISOString(),
      createdBy: 'admin',
      expiresAt: null,
      lastUsedAt: null,
    });
    const stored = JSON.stringify(db.$client.prepare('SELECT * FROM api_keys').all());
    expect(stored).not.toContain(key);
    expect(stored).not.toContain(key.slice(8));
  });

  it('expire after their chosen time, or never', () => {
    const day = 24 * 60 * 60 * 1000;
    expect(expiry('never')).toBeNull();
    expect(expiry('1d')).toBe(new Date(NOW.getTime() + day).toISOString());
    expect(expiry('7d')).toBe(new Date(NOW.getTime() + 7 * day).toISOString());
    expect(expiry('30d')).toBe(new Date(NOW.getTime() + 30 * day).toISOString());
    expect(expiry('1y')).toBe(new Date(NOW.getTime() + 365 * day).toISOString());
  });

  it('are found by the key itself, with their permissions, until they expire', () => {
    const { db, apiKey, key } = withKey('1d');
    const holder = { id: apiKey.id, name: 'Stream Deck', permissions: ['demo:things.read'] };
    expect(findApiKey(db, key, NOW)).toEqual(holder);
    expect(findApiKey(db, key, minutes(24 * 60 - 1))).toEqual(holder);
    expect(findApiKey(db, key, minutes(24 * 60))).toBeNull();
    expect(findApiKey(db, `${key}x`, NOW)).toBeNull();
  });

  it('are gone once revoked', () => {
    const { db, apiKey, key } = withKey();
    expect(revokeApiKey(db, apiKey.id)).toBe(true);
    expect(findApiKey(db, key, NOW)).toBeNull();
    expect(revokeApiKey(db, apiKey.id)).toBe(false);
  });

  it('record when they were last used, at most once a minute', () => {
    const { db, key } = withKey();
    const lastUsed = () => listApiKeys(db)[0]?.lastUsedAt;
    findApiKey(db, key, NOW);
    expect(lastUsed()).toBe(NOW.toISOString());
    findApiKey(db, key, new Date(NOW.getTime() + 59_000));
    expect(lastUsed()).toBe(NOW.toISOString());
    findApiKey(db, key, minutes(1));
    expect(lastUsed()).toBe(minutes(1).toISOString());
  });

  it('are listed newest first, expired ones included, and keep their names unique', () => {
    const { db } = withKey('1d');
    createApiKey(db, { name: 'Companion', permissions: [], expiresIn: 'never', createdBy: 'admin' }, minutes(5));
    expect(listApiKeys(db).map((k) => k.name)).toEqual(['Companion', 'Stream Deck']);
    expect(apiKeyNameTaken(db, 'Companion')).toBe(true);
    expect(apiKeyNameTaken(db, 'companion')).toBe(false);
  });
});
```

Create `rcl-core/server/src/auth/api-key-requests.test.ts`:

```ts
import { afterEach, describe, expect, it } from 'vitest';
import type { InjectOptions } from 'fastify';
import type { AppModule } from '@rollcall/app-sdk';
import type { ApiKeyExpiry } from '@rollcall/core-contract';
import { addUser, testApp } from '../testing.ts';
import { createApiKey, revokeApiKey } from './api-keys.ts';
import { SESSION_COOKIE } from './guard.ts';
import { createSession } from './sessions.ts';

// What the POST route does halfway through, after its await: a test can revoke the key there.
let midRequest: () => void = () => undefined;
afterEach(() => {
  midRequest = () => undefined;
});

// A hosted app with two permissions an API key may hold and one only people may, and a route needing each.
const DEMO_APP: AppModule = {
  id: 'demo',
  title: 'Demo',
  version: '1.0.0',
  requiresCore: '*',
  permissions: [
    { key: 'demo:things.read', summary: 'Read things', roles: ['producer'] },
    { key: 'demo:things.edit', summary: 'Edit things', roles: ['producer'] },
    { key: 'demo:secrets.read', summary: 'Read secrets', roles: [], peopleOnly: true },
  ],
  register(api) {
    api.get('/things', { config: { access: { permission: 'demo:things.read' } } }, async () => ({ things: [] }));
    api.post('/things', { config: { access: { permission: 'demo:things.edit' } } }, async (request, reply) => {
      await Promise.resolve();
      midRequest();
      const denial = request.recheckAccess();
      return denial ? reply.code(denial.status).send({ error: denial.error }) : { ok: true };
    });
    api.get('/secrets', { config: { access: { permission: 'demo:secrets.read' } } }, async () => ({ secrets: [] }));
  },
};

const DAY_MS = 24 * 60 * 60 * 1000;

function withDemo() {
  const { app, db } = testApp({ apps: [DEMO_APP] });
  let keys = 0;
  const keyFor = (permissions: string[], expiresIn: ApiKeyExpiry = 'never', now = new Date()) =>
    createApiKey(db, { name: `key ${(keys += 1)}`, permissions, expiresIn, createdBy: 'admin' }, now);
  const call = (
    method: 'GET' | 'POST',
    url: string,
    { headers = {}, cookies = {} }: { headers?: Record<string, string>; cookies?: Record<string, string> } = {},
  ) => app.inject({ method, url, headers, cookies, ...(method === 'POST' ? { payload: {} } : {}) } as InjectOptions);
  return { app, db, keyFor, call };
}

const bearer = (key: string) => ({ authorization: `Bearer ${key}` });

describe('a request with an API key', () => {
  it('gets through to routes whose permission the key holds, and no further', async () => {
    const { keyFor, call } = withDemo();
    const { key } = keyFor(['demo:things.read']);
    expect((await call('GET', '/api/demo/things', { headers: bearer(key) })).json()).toEqual({ things: [] });
    expect((await call('POST', '/api/demo/things', { headers: bearer(key) })).json()).toEqual({ error: 'forbidden' });
  });

  it('is refused with a wrong, revoked or expired key, or a header that is not a bearer key', async () => {
    const { db, keyFor, call } = withDemo();
    const revoked = keyFor(['demo:things.read']);
    revokeApiKey(db, revoked.apiKey.id);
    const expired = keyFor(['demo:things.read'], '1d', new Date(Date.now() - 2 * DAY_MS));
    const { key } = keyFor(['demo:things.read']);
    for (const authorization of [
      'Bearer rcl_not-a-real-key',
      `Bearer ${revoked.key}`,
      `Bearer ${expired.key}`,
      'Bearer',
      `Basic ${key}`,
      '',
    ]) {
      const res = await call('GET', '/api/demo/things', { headers: { authorization } });
      expect(res.statusCode, authorization).toBe(401);
      expect(res.json(), authorization).toEqual({ error: 'unauthenticated' });
    }
  });

  it('keeps public routes open', async () => {
    const { call } = withDemo();
    expect((await call('GET', '/api/core/health', { headers: bearer('rcl_not-a-real-key') })).statusCode).toBe(200);
  });

  it("ignores the session cookie, even an Admin's", async () => {
    const { db, keyFor, call } = withDemo();
    const admin = await addUser(db, 'admin', 'correct horse', 'admin');
    const cookies = { [SESSION_COOKIE]: createSession(db, admin.id).token };
    const { key } = keyFor([]);
    expect((await call('GET', '/api/demo/things', { cookies })).statusCode).toBe(200);
    expect((await call('GET', '/api/demo/things', { cookies, headers: bearer('rcl_wrong') })).statusCode).toBe(401);
    expect((await call('GET', '/api/demo/things', { cookies, headers: bearer(key) })).statusCode).toBe(403);

  name: row.name,
  prefix: row.tokenPrefix,
  permissions: row.permissions,
  createdAt: row.createdAt,
  createdBy: row.createdBy,
  expiresAt: row.expiresAt,
  lastUsedAt: row.lastUsedAt,
});

/** Creates a key. The key itself is in this reply only; the database keeps its hash. */
export function createApiKey(
  db: Queryable,
  input: { name: string; permissions: readonly string[]; expiresIn: ApiKeyExpiry; createdBy: string },
  now = new Date(),
): { apiKey: ApiKey; key: string } {
  const key = `${API_KEY_PREFIX}${newToken()}`;
  const lifetime = LIFETIMES[input.expiresIn];
  const row = {
    id: randomUUID(),
    name: input.name,
    tokenHash: hashToken(key),
    tokenPrefix: key.slice(0, SHOWN_LENGTH),
    permissions: [...input.permissions],
    createdAt: now.toISOString(),
    createdBy: input.createdBy,
    expiresAt: lifetime === null ? null : new Date(now.getTime() + lifetime).toISOString(),
    lastUsedAt: null,
  };
  db.insert(apiKeys).values(row).run();
  return { apiKey: toApiKey(row), key };
}

/** Every key, newest first, expired ones included. */
export function listApiKeys(db: Queryable): ApiKey[] {
  return db.select().from(apiKeys).orderBy(desc(apiKeys.createdAt)).all().map(toApiKey);
}

export function apiKeyNameTaken(db: Queryable, name: string): boolean {
  return db.select({ id: apiKeys.id }).from(apiKeys).where(eq(apiKeys.name, name)).get() !== undefined;
}

/** Deletes a key; false if there was none. Devices and scripts using it are refused from the next request. */
export function revokeApiKey(db: Queryable, id: string): boolean {
  return db.delete(apiKeys).where(eq(apiKeys.id, id)).run().changes > 0;
}

/** The key `key` names, unless it's unknown or expired. Records its use, at most once a minute. */
export function findApiKey(db: Queryable, key: string, now = new Date()): ApiKeyHolder | null {
  const row = db
    .select()
    .from(apiKeys)
    .where(eq(apiKeys.tokenHash, hashToken(key)))
    .get();
  if (!row || (row.expiresAt !== null && Date.parse(row.expiresAt) <= now.getTime())) return null;
  if (row.lastUsedAt === null || now.getTime() - Date.parse(row.lastUsedAt) >= LAST_USED_RESOLUTION_MS) {
    db.update(apiKeys).set({ lastUsedAt: now.toISOString() }).where(eq(apiKeys.id, row.id)).run();
  }
  return { id: row.id, name: row.name, permissions: row.permissions };
}

export function isServerMachine(request: FastifyRequest): boolean {

const BEARER = /^Bearer\s+(\S+)\s*$/i;

 * The caller a request's credentials identify. An `Authorization` header, when present, is all that counts: a valid
 * `Bearer` API key, or nobody, and the session cookie is ignored (ADR-0020). Otherwise it's the session cookie's user.
 * Output tokens are resolved here too once they exist.
 */
export function resolvePrincipal(
  db: AppDatabase,
  { cookies, authorization }: { cookies: Record<string, string | undefined>; authorization?: string },
): Principal | null {
  if (authorization !== undefined) {
    const bearer = BEARER.exec(authorization)?.[1];
    const key = bearer ? findApiKey(db, bearer) : null;
    return key ? { kind: 'apiKey', key } : null;
  }

  const session = token ? findSession(db, token) : null;
  return token && session ? { kind: 'session', user: session.user, token } : null;
}

// Runs inside the /api plugin: the CSRF check, then the caller onto the request. Each route's access is enforced
// separately, by enforceRouteAccess in access.ts.
export function installAuth(app: FastifyInstance, { db, permissions }: { db: AppDatabase; permissions: Permissions }) {
  app.decorateRequest('principal', null);
  app.decorateRequest('recheckAccess', function (this: FastifyRequest) {
    this.principal = resolvePrincipal(db, credentials(this));
    const { access } = this.routeOptions.config;
    return access ? deny(access, this.principal, permissions) : { status: 403, error: 'forbidden' };
  });

    // A request with an Authorization header comes from a device or script, not a forged cross-site form: browsers
    // never add that header on their own, and the session cookie is ignored for it (ADR-0020).
    const fromBrowser = request.headers.authorization === undefined;
    if (

      !isSameOrigin(request.headers.origin, request.headers.host)
    ) {
      return reply.code(403).send({ error: 'cross_origin' });
    }
    request.principal = resolvePrincipal(db, credentials(request));
    return undefined;
  });
}

  try {
    return new URL(origin).host === host;

    return false; // includes "null"
  }
}

        tags: ['core/auth'],
        summary: 'Change your own password',
        body: ChangePasswordRequestSchema,

    async (request, reply) => {
      const user = userOf(request.principal);
      if (!user) return reply.code(401).send(UNAUTHENTICATED);
      const { currentPassword, newPassword } = request.body;
      if (newPassword.toLowerCase() === user.username) {
        return reply.code(400).send({ error: 'validation_failed', message: 'The password must not be the username' });
      }
      const record = findUserForLogin(db, user.username);
      if (!record || !(await verifyPassword(currentPassword, record.passwordHash))) {
        return reply.code(400).send({ error: 'wrong_password' });
      }
      const passwordHash = await hashPassword(newPassword);
      // Signed out (by an Admin's reset, say) while the password was hashing: don't overwrite the reset.
      const denial = request.recheckAccess();
      if (denial) return reply.code(denial.status).send({ error: denial.error });
      setPassword(db, record.id, passwordHash, { mustChangePassword: false });
      if (request.principal?.kind === 'session') {
        revokeUserSessions(db, record.id, { exceptToken: request.principal.token });
      }
      return { ...user, mustChangePassword: false };
    },
  );
}

  { send }: Inventory,
  routes: readonly ApiRoute[],
  caller: () => Promise<Credentials>,
  { status, error }: { status: number; error: string },

const MANAGE_KEYS: { config: { access: Access } } = { config: { access: { permission: 'core:api-keys.manage' } } };

// API keys for devices and scripts (ADR-0020). Only people may manage them: core:api-keys.manage is people-only. The
// checks run with no `await` before their write, so two requests can't both take a name.
export function registerApiKeyRoutes(fastify: FastifyInstance, db: AppDatabase): void {
  const api = fastify.withTypeProvider<ZodTypeProvider>();

  api.get(
    '/api-keys',
    {
      ...MANAGE_KEYS,
      schema: {
        tags: ['core/api-keys'],
        summary: 'List API keys, newest first',
        response: { 200: ApiKeySchema.array(), ...ERROR_RESPONSES },
      },
    },
    async () => listApiKeys(db),
  );

  api.get(
    '/api-keys/grantable',
    {
      ...MANAGE_KEYS,
      schema: {
        tags: ['core/api-keys'],
        summary: 'The permissions an API key may hold',
        response: { 200: GrantablePermissionSchema.array(), ...ERROR_RESPONSES },
      },
    },
    async (request) =>
      request.server.hostedApps.permissions.all
        .filter((def) => !def.peopleOnly)
        .map(({ key, summary }) => ({ key, summary })),
  );

  api.post(
    '/api-keys',
    {
      ...MANAGE_KEYS,
      schema: {
        tags: ['core/api-keys'],
        summary: 'Create an API key; the key appears in this reply only',
        body: CreateApiKeyRequestSchema,
        response: { 201: CreateApiKeyResponseSchema, ...ERROR_RESPONSES },
      },
    },
    async (request, reply) => {
      const user = userOf(request.principal);
      if (!user) return reply.code(401).send({ error: 'unauthenticated' });
      const { name, permissions, expiresIn } = request.body;
      const hosted = request.server.hostedApps.permissions;
      const grantable = (key: string) => {
        const def = hosted.find(key);
        return def !== undefined && !def.peopleOnly;
      };
      const refused = permissions.filter((key) => !grantable(key));
      if (refused.length > 0) {
        return reply
          .code(400)
          .send({ error: 'not_grantable', message: `An API key can't hold ${refused.join(', ')}.` });
      }
      if (apiKeyNameTaken(db, name)) return reply.code(409).send({ error: 'name_taken' });
      const created = createApiKey(db, {
        name,
        permissions: [...new Set(permissions)],
        expiresIn,
        createdBy: user.username,
      });
      return reply.code(201).send(created);
    },
  );

  api.delete(
    '/api-keys/:id',
    {
      ...MANAGE_KEYS,
      schema: {
        tags: ['core/api-keys'],
        summary: 'Revoke an API key: devices and scripts using it stop working at once',
        params: ApiKeyParamsSchema,
        response: { 204: z.undefined(), ...ERROR_RESPONSES },
      },
    },
    async (request, reply) =>
      revokeApiKey(db, request.params.id) ? reply.code(204).send() : reply.code(404).send({ error: 'not_found' }),
  );
}

  text: string;

---
title: API keys for devices and scripts

# 0020. API keys for devices and scripts

## Context

Devices and scripts on the venue network, such as Bitfocus Companion, a Stream Deck or a laptop script, need to call rcl-core without a browser session. [ADR-0018](0018-declared-access-and-permissions.md) planned API keys: a bearer token, hashed at rest and scoped to permissions. Building them needs answers to four questions:
- how a key fits the access checks;
- which permissions it may hold;
- how long it lasts;
- what it means for the cross-site check.

Options considered for how a key fits the access checks:
- **A key acts as the Admin who made it, limited to what both hold.** Rejected: demoting or deleting that Admin silently breaks every device using the key.
- **A key is a stand-in user with a hidden role.** Rejected: roles are a fixed list, and a hidden one would leak into user lists and permission tables.
- **A key is its own kind of caller, with its own permissions.** Chosen.

## Decision

- **An API key is its own kind of caller,** next to signed-in sessions. It has no user and no role, only the permissions it was given. Keys belong to the server, not to the Admin who made them.
- **The `Authorization` header beats the cookie.** When a request has one, only it counts:
  - `Bearer <key>` with a known, unexpired key is that key;
  - anything else means no caller, so the request gets `401`.

  The session cookie is never used as a fallback.
- **No cross-site check for keys.** Browsers never add an `Authorization` header to a cross-site request on their own, and the cookie is ignored once the header is there. So the Origin check is skipped for such requests.
- **What a key may call:** public routes, and routes that need a permission the key holds. Routes for any signed-in user refuse keys with `403`, because they're about a person.
- **People-only permissions.** A permission may say `peopleOnly: true`.
  - It can never go on a key, and a key holding one is refused anyway.
  - Account administration is people-only: `core:users.manage` and `core:api-keys.manage`. So a leaked key can't create accounts, reset passwords or make more keys.
- **Keys:**
  - A key is `rcl_` followed by 32 random bytes. It's shown once and stored as a SHA-256 hash, with its first 8 characters kept so a person can tell keys apart.
  - It has an optional expiry from presets: never, 1 day, 7 days, 30 days or 1 year.
  - A key can't be edited: create a new one and revoke the old. Revoking deletes the key.
- **HTTP only for now.** Socket.IO namespaces ignore the `Authorization` header, so live connections need a session.

## Consequences

- **Precise and revocable.** Devices and scripts get exactly the permissions they need, and lose them the moment their key is revoked.
- **Handlers must allow for keys.** Every handler that reads the signed-in person must allow for a key: `userOf(request.principal)` gives the person, or nothing for a key.
- **Each new permission decides whether it's people-only.** The users-and-access permission table shows it, and a test keeps the table in step with the code.
- **Keys start out limited to public routes,** until a feature adds a permission keys may hold.
- **Plain HTTP exposes keys.** Until HTTPS arrives, keys cross the venue network in the clear, as passwords do.
- **Live connections need a new decision.** Letting devices open them means accepting keys on namespaces.
```
